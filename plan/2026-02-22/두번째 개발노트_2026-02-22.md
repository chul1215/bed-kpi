## ✅ DRG 매칭 문제 해결: 진단명 기반 매칭 완료

### 해결 개요
진단명 직접 매칭 방식으로 전환하여 46개 진단명 매칭 완료, 의료진 데이터 표시율 76% 달성

### 통계 (대전 비수기 기준)
- **진단명 매칭률**: 14.2% (46개 / 324개)
- **의료진 데이터 표시**: 76% (32명 / 42명에게 KPI 데이터 표시)
- **환자 커버리지**: 약 30% (추정)
- **매칭 방식**: 수동 15개 + 자동 31개 (직접 일치 + 부분 일치)

### 해결 방법
**진단명 기반 직접 매칭 (Diagnosis-Based Matching)**

| 구분 | DRG 코드 매칭 (실패) | 진단명 매칭 (성공) |
|------|---------------------|-------------------|
| 분류 체계 | HIRA DRG vs SMC 진단명 | HIRA ADRG명 vs SMC 진단명 |
| 중심 | 수술/시술 코드 | 진단명 직접 비교 |
| 예시 | "담석증" → DRG 코드 매칭 실패 | "담석증" → "복강경을 이용한 전담낭절제술" |
| 매칭 전략 | 3단계: 수동 매핑 → 직접 일치 → 부분 일치 |

### 구체적 사례

**매칭 성공 (46개 진단명)**:
- 협심증 → 협심증 (직접 일치)
- 급성 충수염 → 복잡한 주진단이 없는 충수절제술 (수동 매핑)
- 담석증 → 복강경을 이용한 전담낭절제술 (수동 매핑)
- 상세불명 병원체의 폐렴 → 세균성 폐렴 (수동 매핑)
- 대퇴골 골절 → 대퇴골 골절 (직접 일치)
- 무릎관절증 → 슬관절전치환술 (수동 매핑)
- 뇌경색증 → 뇌경색증 (직접 일치)

**매핑 구성**:
- 수동 매핑: 15개 (diagnosis_drg_mapping.xlsx)
- 자동 매칭: 31개 (직접 일치 + 부분 일치)

**매칭 실패 (여전히 남은 진단명)**:
- 기타 의학적 관리... (일반적인 ADRG와 매칭 어려움)
- 위장염 (HIRA ADRG에 정확히 대응하는 항목 없음)
- 전정기능 장애 (매칭 가능한 ADRG 없음)

### 개선 결과

#### 1. 시스템 기능 정상화 (대전 비수기 기준)
```
KPI 지표          변경 전        →  변경 후
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
데이터 표시 의료진  0명 / 42명    →  32명 / 42명 (76%)

현재 가동률        90.64%       →  90.64% (정상)

```

#### 2. 대시보드 표시 정상화

- ✅ 요약 KPI: 평균 LOS 갭 -0.41일 (매칭 성공 데이터 기준)
- ⚠️ 나머지 10명: "매칭 실패" 상태 (데이터 없음)

#### 3. 비즈니스 영향
- ✅ 76% 의료진에게 심평원 기준 대비 개선 목표 제시 가능
- ✅ 주요 진단명(상위 30%)에 대한 의사 결정 근거 확보

### 방안 3: 상대 비교 시스템으로 전환 (즉시 가능)

**개요**: 심평원 기준 없이 병원 내부 데이터로 상대 비교

**KPI 재정의**:
```python
# 기존 (절대 기준)
los_gap = hira_target_los - current_los

# 변경 (상대 기준)
los_gap = current_los - hospital_avg_los  # 병원 평균 대비
# 또는
los_gap = current_los - dept_avg_los      # 진료과 평균 대비
```

**장점**:
- ✅ 즉시 구현 가능 (1-2일)
- ✅ 매칭 작업 불필요
- ✅ 의사간 상대 비교로 충분한 인사이트

**단점**:
- ❌ 외부 벤치마크 없음
- ❌ 절대적 개선 목표 제시 불가
- ❌ 병원 전체 비효율 감지 어려움

**예시**:
```
정윤화 의사 (IMO)

환자수:        487명
현재 LOS:      7.81일
진료과 평균:   6.50일
━━━━━━━━━━━━━━━━━━━━━━━━━
LOS 갭:        +1.31일
개선 필요도:   높음
```

**템플릿 수정**:
```jinja2
<!-- 기존 -->
{% if doctor.los_gap >= 0 %}

<!-- 수정 -->

    {% if doctor.los_gap >= 0 %}
        <span class="positive">+{{ "%.1f"|format(doctor.los_gap) }}일</span>
    {% else %}
        <span class="negative">{{ "%.1f"|format(doctor.los_gap) }}일</span>

{% endif %}
```

- `disease.html`
- `department.html`
- `index.html`

### 3. 정적 HTML 경로 수정 (완료 ✅)

**문제**: 절대 경로(`/upload`, `/department`) 사용으로 file:// 프로토콜에서 작동 불가

**해결**:
```python
# 같은 디렉토리 레벨
html = html.replace('href="/upload"', f'href="index_{period}.html"')
html = html.replace('href="/"', f'href="index_{period}.html"')
html = html.replace('href="/department"', f'href="department_{period}.html"')

# 서브디렉토리 (doctors_*, diseases_*)
html = html.replace('href="/"', f'href="../index_{period}.html"')
html = html.replace('href="/department"', f'href="../department_{period}.html"')
```

**결과**:
- ✅ HTML 파일 더블클릭으로 바로 실행 가능
- ✅ 서버 불필요
- ✅ USB/로컬 공유 가능

- **문제**: 서버 기능 (업로드, 동적 필터링) 구현 후 제거
