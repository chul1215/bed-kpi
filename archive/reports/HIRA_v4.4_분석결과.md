## 🔍 핵심 발견사항

### 1. 매칭 성능은 동일

**결론**: ADRG 레벨에서 매칭하는 한, 기존 파일과 신규 v4.4 파일의 성능 차이는 **없음**

- 신규 v4.4 파일은 DRG 레벨 (중증도 세분화) 데이터 제공
- ADRG로 집계하면 동일한 ADRG명과 평균재원일수 생성
- 부분 일치 알고리즘은 ADRG명 기반이므로 결과 동일

### 2. 매칭률이 매우 낮음 (6.7%)

**문제의 핵심**:
- 384개 진단명 중 39개만 매칭 (10.2%)
- 3,740명 환자 중 251명만 커버 (6.7%)
- **이것이 "남선우 의료진 45명 중 12명만 표시" 문제의 근본 원인**

**현재 매칭 전략**:
1. 수동 매핑 테이블 우선 (현재 없음 또는 매우 제한적)
2. 진단명 = ADRG명 직접 일치
3. 진단명 in ADRG명 or ADRG명 in 진단명 (부분 일치)

### 3. 병원 데이터에 DRG 코드가 없음

**SMC 파일 구조**:
```
컬럼: ['구분', '퇴원일자', '성별', '입원일자', '평균재원', '퇴원과', '진단명', '의사명']
```

**샘플 진단명**:
- 급성 충수염
- 장의 기타 질환
- 기타 의학적 관리를 위하여 보건서비스와 접하고 있는 사람
- 전정기능의 장애

**문제**:
- 병원 데이터에는 **진단명(한글 텍스트)만 있고 DRG 코드가 없음**
- ICD-10 코드도 없음
- 따라서 **진단명을 ADRG명과 텍스트 매칭**하는 방법밖에 없음

## 💡 해결 방안

### 방안 1: 수동 매핑 테이블 대폭 확장 (권장) ⭐

**현황**:
- 현재 수동 매핑이 없거나 매우 제한적 (0개 추정)
- 부분 일치만으로 39개 진단명 매칭 (10.2%)

**개선 방법**:
1. **상위 100개 진단명 수동 매핑**
   ```bash
   cd backend
   python3 -c "
   from app.services.kdrg_matcher import KDRGMatcher
   from app.services.file_parser import FileParser
   from pathlib import Path

   matcher = KDRGMatcher()
   smc_df = FileParser.parse_smc_file('../data/smc/...')
   hira_df = FileParser.parse_hira_file('../data/hira/...')

   matcher.generate_mapping_template(
       smc_df, hira_df,
       Path('../data/mapping/diagnosis_kdrg44_mapping_template.xlsx'),
       top_n=100
   )
   "
   ```

2. **매핑 템플릿 수동 작성**
   - `data/mapping/diagnosis_kdrg44_mapping_template.xlsx` 열기
   - "매핑템플릿" 시트에서 `adrg_name` 컬럼 작성
   - "ADRG목록" 시트 참조하여 적절한 ADRG명 선택

3. **매핑 파일 저장**
   - `data/mapping/diagnosis_kdrg44_mapping.xlsx`로 저장
   - 컬럼: `diagnosis`, `adrg_name`

**예상 효과**:
- 상위 100개 진단명 매핑 시 환자 커버리지 **60%+** 예상
- 남선우 의료진 같은 케이스 대폭 개선

---

### 방안 2: 병원 시스템에서 DRG 코드 포함 데이터 확보

**문제**:
- 현재 병원 데이터에 DRG 코드가 없음
- 진단명(한글 텍스트)만 있어서 정확한 매칭 어려움

**해결책**:
1. **병원 EMR 시스템에서 DRG 코드 추출**
   - DRG 청구 데이터는 반드시 DRG 코드 포함
   - 진료비 청구 부서에 요청하여 DRG 코드 포함 데이터 확보

2. **ICD-10 코드 추가**
   - ICD-10 → DRG 변환 알고리즘 적용
   - 더 정확한 매칭 가능

**예상 효과**:
- DRG 코드 직접 매칭 시 **90%+** 커버리지 가능
- 텍스트 매칭의 불확실성 제거

---

### 방안 3: 미매칭 진단명도 토글에 표시 (임시 해결)

**현재 문제**:
- `calculate_doctor_disease_kpis()` 함수가 `target_los`가 없는 진단명 제외
- 남선우 의료진: 45명 환자 중 12명만 표시

**개선 방법**:
- 모든 진단명을 토글에 표시
- 미매칭 진단명은 LOS 갭, 추가재원일수를 "N/A"로 표시
- 사용자에게 "이 진단명은 매칭되지 않았음"을 명확히 표시

**장점**:
- 환자수 정합성 확보 (45명 전체 표시)
- 어떤 진단명이 매칭되지 않았는지 확인 가능

**단점**:
- 미매칭 진단명은 KPI 계산 불가능
- 근본적인 해결책은 아님

## 📋 권장 실행 순서

### 즉시 실행 (방안 1)

1. **매핑 템플릿 생성**
   ```bash
   cd backend
   python3 generate_mapping_template.py
   ```

2. **상위 100개 진단명 수동 매핑**
   - `diagnosis_kdrg44_mapping_template.xlsx` 파일 열기
   - 진단명별로 적절한 ADRG명 선택
   - `diagnosis_kdrg44_mapping.xlsx`로 저장

3. **대시보드 재생성**
   ```bash
   python3 generate_static_dashboard.py
   ```

4. **검증**
   - 남선우 의료진 같은 케이스 확인
   - 환자 커버리지 개선 확인

### 중기 실행 (방안 2)

1. **병원 EMR 팀에 요청**
   - DRG 코드 포함 데이터 추출 요청
   - 또는 ICD-10 코드 포함 데이터 요청

2. **데이터 구조 변경**
   - `file_parser.py` 수정 (DRG 코드 컬럼 추가)
   - `kdrg_matcher.py` 수정 (코드 기반 매칭)

3. **전면 재설계**
   - DRG 코드 직접 매칭으로 전환
   - 매칭률 90%+ 달성
